Troubleshooting

Something does not look right? Most problems have a quick fix. And remember: plasmify restore latest undoes the last apply.

On this page

  • The desktop cube does not open

Black screen or missing panels

Some steps need Plasma's shell (plasmashell, which draws the panels and wallpaper) to restart. Plasma only allows a few restarts per minute, so several quick applies in a row could once leave you with a black screen and no panels. Plasmify now handles this: it resets the limit, waits until the shell is back, starts it directly if systemd still refuses, and builds the panels and wallpaper only after the restart, with a check and one retry. If building the panels fails anyway, it falls back to a plain panel.

If you still end up without panels, start the shell yourself. In a terminal that is still open, or one you open with KRunner (Alt+Space), run:

systemctl --user reset-failed plasma-plasmashell
systemctl --user start plasma-plasmashell

If that does not help, start it directly:

kstart plasmashell

If you cannot open any window, switch to a text console with Ctrl+Alt+F3, log in, run the two systemctl commands above, then switch back to your desktop (usually Ctrl+Alt+F1 or Ctrl+Alt+F2, depending on your distribution). As a last resort, log out and back in.

Once the desktop is back, plasmify restore latest undoes the apply if you want. If the apply window said Plasma did not come back after the reload; log out and in to finish, logging out and in completes it.

Panel colour or rounded corners not visible

  • A window touches the panel. While a window touches a panel (a maximised window, for example), Plasma attaches the panel to the screen edge, shows square corners and uses its solid background. Move or restore the window and the floating panel with your colour and corners comes back.
  • Tiling is on. With tiling, windows always touch the panels, so rounded corners only show on an empty desktop. The Customize tab shows a hint about this.
  • The panel does not float. Corners only show on floating panels. Tick Floating (gap around it) for the panel in the panel builder.
  • The corners are capped. The radius can only be a little less than half the thinnest panel (a 32 px bar allows 14 px). Make the panel thicker, or use the Make panels thicker hint.
  • The theme has no panel style of its own. Some presets (Tokyo Night Neon, Nord Minimal, Gruvbox Retro, Rosé Pine Cozy and Catppuccin Anime) leave the panels to your own Plasma style, so the corners and colour of an earlier preset go away. The Customize tab says so under Panel style. Change any setting there to give the panels Plasmify's corners, opacity, colour and border.
  • The step was off. For a theme with a panel style, check that Panel style is ticked in the What to apply tab.

A dock or panel keeps hiding

A panel set to Hides when a window touches it stays hidden while windows touch it, which with tiling is all the time. Push the mouse to that screen edge to show it, or set its visibility to Always visible (the Keep it visible hint does this for you).

The living wallpaper pauses or stays still

  • It pauses when a window is maximised. That is Plasma: it pauses moving wallpapers while a window fills the screen, to save processor time and battery, and plays them again when the desktop shows. To keep them moving anyway, tick Keep moving while windows are open in the Wallpapers section of the Customize tab (or run plasmify set shimmer-always on) and apply.
  • Only some pictures move. Shimmer brings the first six pictures of a slideshow to life; the others take their turn as still pictures. Reorder the thumbnails to choose which ones move.
  • Nothing moves at all. Look at the apply window's notes. Qt cannot write WebP pictures on this system means Qt's image formats plugin is missing; install it with your package manager (on Arch it is qt6-imageformats) and apply again. A note such as … stays still names a picture that could not be brought to life.
  • The lock screen does not move. That is on purpose: the lock screen, the splash screen and the login screen keep the still picture.

Windows do not turn to glass

  • Restart the app. Apps that were open when you applied turn to glass after you close and open them again.
  • The window you are using stays solid. That is on purpose, in every look: only the windows behind it are see-through, so their text never shows through yours. Click another window and the one you left turns to glass. To see through the window you use as well, untick Keep the window you use solid in the Glass section (plasmify set focused-solid off).
  • Glass needs Kvantum, and Frosted and Glass need blur. Plasmify installs Kvantum from your distribution and turns blur on when you apply Frosted or Glass. Check that Application style and Effects are ticked in the What to apply tab, and that blur is still on in System Settings (Desktop Effects).
  • Your screen scale is between whole numbers. At 125 % or 150 %, Kvantum keeps windows solid; glass shows at 100 % or 200 %. The apply window warns about this.
  • Some apps stay solid on purpose. Photo, video and drawing apps (Krita, OBS, LibreOffice, Gwenview, showFoto, Kdenlive, Shotcut, digiKam, VLC, SMPlayer) keep solid windows, and so do apps the Kvantum theme itself lists.
  • Only part of a window is see-through. Glass makes window backgrounds see-through. Many apps paint their main area themselves (the text of an editor, a web page, a document), and that area stays solid. Dolphin shows the effect everywhere, so try it there first.
  • It looks frosted, not see-through. Frosted is only a little see-through, with a strong blur. Choose Glass or Clear in the Glass section, or move the See-through slider up (plasmify set glass glass or plasmify set transparency 50% from a terminal).
  • Text is hard to read. Where windows overlap, make sure Keep the window you use solid is ticked (it is unless you turned it off; plasmify set focused-solid on turns it back on), so the text of a window behind never shows through the one you work in. Move the See-through slider down or choose Frosted, whose blur calms a busy wallpaper. Light palettes start with less see-through for this reason.
  • A note says a theme was left alone. A Kvantum theme folder with the name Plasmify wanted (<theme>-glass or plasmify-glass) already exists in ~/.config/Kvantum and was not made by Plasmify, so it is never replaced. Rename or remove it and apply again.
  • A note says Breeze is used instead. The glass template could not be downloaded, or it did not match its checksum. Apply again later.

The desktop cube does not open

Press Meta+C to open it. If nothing happens:

  • The cube effect is not installed. KWin does not ship it, and Plasmify does not install it; the apply window names the package to install: kdeplasma-addons on Arch and Fedora, kdeplasma6-addons on openSUSE, kwin-addons on Debian and Ubuntu. Install it and apply again.
  • There are fewer than three virtual desktops. The cube needs at least three. Add them in System Settings, Virtual Desktops; Plasmify never changes how many you have.

The terminal photo looks blocky

Photos are drawn as real images only in terminals that support it: Konsole, kitty, Ghostty and WezTerm (through the kitty graphics protocol) and foot (through sixel). Every other terminal, Alacritty for example, shows the photo as coloured text blocks, which looks coarser.

  • Use one of the terminals above for a sharp photo.
  • Inside tmux, screen or an SSH session the terminal may not be recognised, so you get the text-block version.
  • For a crisp look in any terminal, choose My own text, My own drawing or a fastfetch logo instead.

Fonts missing, or boxes in the prompt

  • The Customize tab only lists installed fonts. To use another font, install it first (with your package manager or System Settings), then reopen Plasmify.
  • A preset's fonts are installed from your distribution's repositories when you apply. Fonts your distribution does not package are downloaded for your user only into ~/.local/share/fonts/plasmify. If a download failed, the apply window lists it as a note; the download history shows the details. Applying again retries it.
  • Boxes or question marks in the prompt mean the symbols font for prompt icons is missing. It is installed with the Shell prompt step (unless the prompt is off). Apply again with Shell prompt ticked.
  • Apps that were already open may only pick up new fonts after a restart. You can check whether a font is installed with fc-list | grep -i "font name".

Konsole opens bash instead of my shell

Terminals usually start the shell named in $SHELL. After you change your shell with chsh, that variable keeps the old value until your whole session restarts, so Konsole keeps opening bash. Plasmify works around this: its Konsole (and Alacritty) settings start your login shell from your account directly, as long as that shell is listed in /etc/shells.

  • Apply again with Terminal ticked, so Plasmify writes your current login shell into its Konsole profile.
  • Check your login shell with getent passwd "$USER" (the last field) and that it appears in /etc/shells.
  • Or simply log out and back in, which refreshes $SHELL everywhere.

Apply theme is greyed out

  • While the summary says Checking what needs to be installed…, Plasmify is working out the packages for your current settings. Apply becomes available when it is done.
  • If a red banner is shown at the top of the window, Plasmify found a problem with your system (for example, you are not in a Plasma 6 session, or a Plasma tool is missing). Fix what it names and restart Plasmify.
  • If the summary says These settings are not valid, a Customize setting cannot be used as it is; the message says which one.

Error log and download history

  • Error log: if Plasmify hits an unexpected error, it does not close; it shows a message and writes the details to ~/.local/state/plasmify/errors.log. Please attach that file to bug reports.
  • Apply log: the apply window shows every step and any notes. On the command line, plasmify apply <preset> prints the same.
  • Download history: File > Download history… or plasmify log lists the files, git sources, fonts and packages Plasmify fetched, newest first, with sizes, checksums and errors. plasmify log shows the newest 50; add -n with a number to see more. The history is stored in ~/.local/state/plasmify/activity.jsonl and never leaves your computer.

Reporting a bug

Please open an issue on the project's page using the bug report template, and include:

  • the output of plasmify --version;
  • your distribution (cat /etc/os-release) and Plasma version (plasmashell --version);
  • the preset and the steps you applied;
  • the output of the failing command (plasmify apply <preset> prints every step), or the log from the apply window;
  • ~/.local/state/plasmify/errors.log, if it exists.

Security problems should not go into a public issue; see Security and privacy.
