Install

Plasmify installs into your home folder in a few seconds. Root is only needed if Python, PyQt6 or git is missing.

Requirements

  • KDE Plasma 6 on Wayland. X11 also works on Plasma versions that still offer an X11 session; Plasma 6.8 dropped it. Plasmify runs inside your Plasma session.
  • Python 3.11 or newer, PyQt6 and git. The installer adds whichever of them are missing.
  • For living wallpapers: Qt's image formats plugin (WebP support), which most Plasma desktops already have. Without it, the wallpapers simply stay still. Kvantum, which glass and some presets use, is installed by Plasmify itself when it is needed.
  • A distribution from one of these families:
FamilyExamplesPackage managerStatus
ArchArch Linux, CachyOS, EndeavourOS, Manjaro, GarudapacmanTested on real hardware
FedoraFedora KDE 43+, NobaradnfTested in a Fedora 44 KDE virtual machine, package names checked in CI
openSUSETumbleweed, SlowrollzypperPackage names checked in CI, not yet tested on a desktop
Debian/UbuntuDebian 13+, Kubuntu 25.10+, KDE neon, TUXEDO OSaptPackage names checked in CI, not yet tested on a desktop

Distributions that still ship Plasma 5 (for example Kubuntu 24.04 or openSUSE Leap 15) are not supported. If you use one of the families that are not yet tested on a desktop, a short report in the project's Discussions helps a lot.

Known differences between distributions
  • Fedora: Starship is not in the official repositories, so the Starship prompt is left out there. The fastfetch greeting and zoxide still work. Plasmify will not add a COPR.
  • Fonts a distribution does not package (for example Nunito on Debian, or the Nerd Font symbols everywhere except Arch) are downloaded for your user only, from the Google Fonts repository or the font's own GitHub release.

When the window opens, Plasmify also checks for a few tools that every Plasma 6 desktop has: plasmashell, kwriteconfig6, kreadconfig6, plasma-apply-colorscheme and a D-Bus tool (qdbus for Qt 6, or gdbus). If something is missing, or you are not in a Plasma session, a red banner at the top of the window says what, and Apply theme stays disabled.

Install with install.sh (recommended)

git clone https://github.com/heyquatch/plasmify.git
cd plasmify
./install.sh

The installer:

  1. Checks that Plasma 6 is installed. It stops if plasmashell is missing or older than version 6.
  2. Finds your package manager and checks for Python, PyQt6 and git. Only if one of them is missing does it run sudo to install it, without optional extras (recommended or weak dependencies).
  3. Checks that Python is version 3.11 or newer.
  4. Copies the app into ~/.local/lib/plasmify and adds the plasmify command, the menu entry and the icon (see below). Nothing is written outside your home folder.
Package managerDependencies it checksCommand used if any are missing
pacmanpython python-pyqt6 gitsudo pacman -S --needed
dnfpython3 python3-pyqt6 gitsudo dnf install --setopt=install_weak_deps=False
zypperpython3 python3-PyQt6 gitsudo zypper install --no-recommends
aptpython3 python3-pyqt6 gitsudo apt-get install --no-install-recommends

Where the files go

PathWhat it is
~/.local/lib/plasmify/The app itself (a copy of src/plasmify from the repository)
~/.local/bin/plasmifyThe plasmify command, a tiny launcher script
~/.local/share/applications/io.github.heyquatch.plasmify.desktopThe application menu entry (in the Settings category)
~/.local/share/icons/hicolor/scalable/apps/io.github.heyquatch.plasmify.svgThe app icon

Your presets, downloads, settings and backups are stored separately (in ~/.config/plasmify, ~/.local/share/plasmify and ~/.local/state/plasmify), so reinstalling or updating never touches them.

Another location

Set PREFIX to install somewhere other than ~/.local, for example PREFIX="$HOME/apps" ./install.sh. Use the same PREFIX later for --uninstall.

The PATH note

At the end the installer checks whether ~/.local/bin is in your PATH. If it is not, it prints a note with the command's full path. The application menu entry starts Plasmify by that full path, so it works either way. To use the short plasmify command in a terminal, add the folder to your PATH:

# bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc

# zsh
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc

# fish
fish_add_path ~/.local/bin

Then open a new terminal. Many distributions also add ~/.local/bin to the session's PATH by themselves at the next login, if the folder existed then.

Arch Linux package (PKGBUILD)

On Arch-based systems you can build a regular pacman package instead. The recipe is in packaging/arch/PKGBUILD. It is not in the AUR: you build it yourself from the repository.

cd plasmify/packaging/arch
makepkg -si
  • It downloads the source archive of the release tagged v<pkgver> from the project's GitHub page, builds it, runs the unit tests and installs it with pacman.
  • Files go to the system: the plasmify command to /usr/bin, the Python package to your Python site-packages, the menu entry to /usr/share/applications and the icon to /usr/share/icons/hicolor/scalable/apps.
  • Dependencies: python, python-pyqt6, git, plasma-workspace, kconfig and qt6-tools. kvantum and papirus-icon-theme are optional; Plasmify installs them itself (from your distribution's repositories) when a preset needs them.
  • makepkg -s installs the build tools it needs (python-build, python-installer, python-setuptools, python-wheel).
Pick one way

Use either install.sh or the package, not both. Otherwise you have two copies, and whichever comes first in your PATH (usually the one in ~/.local/bin) is the one that runs. Package users remove Plasmify with pacman, see Uninstall.

Run without installing

You can also run Plasmify straight from the cloned folder, which is handy for trying a branch:

cd plasmify
PYTHONPATH=src python3 -m plasmify gui      # the window
PYTHONPATH=src python3 -m plasmify --help   # the command line

First start

Open Plasmify from the application menu, or type plasmify gui. Other commands, such as plasmify list, work in the terminal, and plasmify on its own lists them (see Command line). Continue with Getting started.
