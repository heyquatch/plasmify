Security and privacy

Plasmify is built so that applying a preset someone shared with you is safe, even if that person means harm. A preset is data, never code.

This page is a short summary for users. The full threat model, with every defence, is in SECURITY.md.

What a shared preset can and cannot do

Every value in a preset is treated as untrusted. Presets are checked against a strict schema before anything happens: every value has a type, a range and an allowed set of characters, unknown keys are errors, and line breaks or control characters are refused everywhere.

A shared preset can

  • Change the parts of your theme that Plasmify offers, within their allowed values
  • Download themes, cursors and wallpapers over HTTPS from GitHub, Codeberg and GitLab
  • Download from other servers after you approve them
  • Ask for packages from a reviewed list, from your distribution's configured repositories, shown to you before you apply
  • Bring its own pictures (checked to really be PNG, JPEG, WebP or GIF images of a sane size)

A shared preset cannot

  • Run code or scripts, or slip extra lines into your terminal, shell or Plasma configuration
  • Choose where files are written or deleted (names are restricted and every path is checked)
  • Install arbitrary packages
  • Contact other servers without asking you
  • Replace or pose as a built-in preset or another preset you have
  • Show fake links or formatting (all preset text is shown as plain text)
  • Smuggle scripts or huge files in a .plasmify bundle (only preset.toml and images are accepted, with size and count limits)

To stop look-alikes, your own and imported presets always show (yours) before their name, invisible and right-to-left characters are refused, and a preset whose colour scheme would clash with one you already have is refused.

Downloads

  • HTTPS only, and download redirects are checked by the same rules. Git downloads follow no redirects at all, so git only ever talks to the server that was checked. Server names must be plain letters, digits, dots and dashes, so a look-alike of a trusted name is refused.
  • Archives are checked before they are unpacked: no paths or links that climb out of the folder, no hard links, and limits on size and file count. One apply may download at most 1.5 GB in total.
  • Git sources are fetched over HTTPS only, without submodules, with symbolic links and Git LFS turned off.
  • Polonium, the one piece of downloaded code, is pinned to a release and checked against its SHA-256 before it is installed.
  • The template for glass (Catppuccin's Kvantum theme, used when a preset has no Kvantum theme of its own) is pinned the same way: it comes from one fixed version and must match its SHA-256 before it is recoloured, or Breeze stays.
  • Pictures are checked before they are opened: the file type comes from the first bytes, never the name, and the size and frame count from the file's header. A picture over 8192 pixels on a side or with more than 1500 frames is refused, so a small file cannot claim to be a huge one and eat your memory.
  • Glass only ever replaces Kvantum theme folders that Plasmify made (they carry a made-by-plasmify.txt file). A theme of yours with the same name is left alone.

Known limits, on purpose: the trusted hosts are trusted for your privacy, not for their content, so theme files from them are installed like any theme you would download yourself. Fonts that a distribution does not package come from the google/fonts repository or the font's own GitHub release, with no pinned checksum; the download history records their SHA-256.

Root for packages and the login screen

Plasmify writes your desktop theme as you, never as root. Installing missing packages uses your package manager through the normal system password prompt; Plasmify calls pkexec and the package manager by their full path. Apart from that, the login screen background is the one thing that runs as root, and everything it does is kept in one small, fixed piece of code:

  • Root never reads a file path a normal program could swap. Plasmify reads the picture as you (refusing links, non-images and files over 50 MB) and hands it to root directly.
  • Root writes it under a fixed name into a folder only root can write (/usr/share/wallpapers/plasmify-login), and sets one or two known settings.
  • Restore never copies a file from your (writable) backup folder as root. It only writes back the values of the settings Plasmify changed, after they match strict patterns.
  • The scripts are fixed text. pkexec, sh and every program the scripts run, kwriteconfig6 included, are called by their full path, never looked up in a search path. If /usr/bin/kwriteconfig6 is missing, Plasmify says so before it asks for your password.

Privacy

  • No telemetry, analytics, accounts or background services. Plasmify only runs while you use it.
  • Plasmify downloads nothing until you apply a preset, and then fetches what that preset needs. Your package manager talks to your distribution's mirrors to install missing packages, and may also do so while Plasmify checks which ones are missing. Nothing is uploaded.
  • Downloads use a generic Python User-Agent; Plasmify does not identify itself or its version.
  • To route downloads through a proxy or Tor, set HTTPS_PROXY.
  • The terminal greeting hides user@host unless you switch it on.
  • Every download and package installation is recorded locally in ~/.local/state/plasmify/activity.jsonl, so you can check what a preset brought in. plasmify log --clear deletes it.
  • Pictures for the theme studio are analysed on your computer.
  • Living wallpapers (Shimmer) are made on your computer from pictures that are already there, and so is their preview. Shimmer never goes online.
  • Backups, downloads and settings stay in your home folder: ~/.local/state/plasmify, ~/.local/share/plasmify and ~/.config/plasmify, plus the usual places for themes, icons and fonts (~/.config/Kvantum, ~/.local/share/icons, ~/.local/share/fonts/plasmify). The exception is the login screen: if you change it, its picture and setting are stored system-wide, as described above.

How it is tested

  • tests/test_security.py has one test for every defence and for every past finding.
  • tests/test_security_fuzz.py puts hostile text into every free-text field and checks that every generated config file, script and splash screen keeps exactly its normal structure.
  • tests/test_bundle_fuzz.py feeds hundreds of corrupted and malicious .plasmify bundles to the importer; each must be refused cleanly without writing outside the preset folder.
  • The root scripts are run as a normal user against a temporary folder in tests/test_screens.py.
  • Continuous integration runs the security lint rules (flake8-bandit through ruff) on every change.
  • Changes to panels, wallpapers and the splash screen are tried in a throwaway Plasma sandbox before they reach a real desktop (see Contributing).

Out of scope: the upstream projects themselves (for example a theme author who ships a malicious theme file), your distribution's packages, and anything you run outside Plasmify.

Reporting a vulnerability

Please do not open a public issue for security problems. Use GitHub's private vulnerability reporting on the project's page (the Security tab, Report a vulnerability). You can expect a first answer within a week. Only the latest release receives fixes. Details are in SECURITY.md.
